## 关键设计决策

### 1. 隔离会话执行

日报生成在独立隔离会话中运行，不与主会话共享上下文，确保：
- 主会话的对话历史不会污染日报生成
- 日报生成的大量中间输出不占用主会话 token 预算
- 失败不影响主会话正常运行

### 2. Cron + Announce 模式

```
Cron Job (isolated) → 完成 → announce → 主会话收到 → 转发用户
```

不使用 Cron 直接推送到 Telegram，而是返回给主会话再处理，因为：
- 主会话可以做二次处理（格式化、补全、纠错）
- 统一消息管理，避免多入口混乱

### 3. LLM Fallback 链

```
DeepSeek V4 Pro → MiMo V2.5 Pro → DeepSeek V4 Flash
```

三梯队保障日报质量，一个挂了自动切下一个。

### 4. 10 次独立搜索 vs 1 次聚合搜索

使用多关键词搜索 + 深度阅读，而非单次搜索：
- 覆盖更广（不同关键词搜出不同结果）
- 深度更深（web_fetch 抓全文，不仅靠摘要）
- 真实来源（基于实际新闻报道，非 LLM 幻觉）

## 扩展性

### 增加用户

一个主会话可以服务多个用户（通过不同 Chat ID）：
```json
"delivery": {
  "mode": "announce",
  "channel": "telegram",
  "to": "user_id_1,user_id_2"
}
```

### 增加日报种类

复制 Cron Job，修改 prompt 即可：
- AI 论文日报（搜 arXiv）
- AI 产品日报（搜 Product Hunt + 新闻）
- AI 创投日报（搜 TechCrunch + 融资新闻）

### 多语言

修改 SerpAPI 搜索参数 `gl` 和 `hl`：
- 中文日报：`gl=cn&hl=zh-CN`
- 日文日报：`gl=jp&hl=ja`
